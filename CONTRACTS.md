# Contracts

Identifiers that live outside this repository: in visitors' browsers, in
bookmarks and search indexes, in files other tools read, in the deployed AI
service, and in its DynamoDB table. Renaming one in the source passes every
test here and breaks every reader of the old name, so each one changes only by
the policy in its row (`DOCUMENTATION-STANDARD.md` §4.1, DOC-23). A pull request
that adds a new identifier of one of these kinds adds its row in the same
change.

| Identifier | Kind | Where | Owner | Change policy |
| --- | --- | --- | --- | --- |
| `permit-bearings:analytics-opt-out` (`1`) | localStorage key and value | `assets/analytics.js` (`OPT_OUT_KEY`) | web pages | Never renamed: a rename silently turns analytics back on for everyone who opted out. A successor must honor the old key |
| `/index.html`, `/check.html`, `/prepare.html`, `/evidence.html`, `/review.html`, `/privacy.html` under `https://chelseakr.github.io/permit-bearings/` | page URLs | repository root (GitHub Pages serves `main`) | web pages | Never moved or removed without a page left at the old path that links to the new one |
| `?sample=<project type>` on `check.html` | URL query parameter | `assets/demo.js` | web pages | Additive only: an existing value keeps working, or falls back to the empty form, never to an error |
| `schemas/facts.schema.json`, `schemas/rule.schema.json`, `schemas/result.schema.json` and their `$id` URLs | published JSON Schema files | `schemas/`, generated by `scripts/gen_schemas.py` | screening contract | Never moved. A breaking change raises `schema_version` and is published beside the old shape |
| `schema_version` and the result envelope's field names | published JSON fields | `src/permit_pathways/screening_contract.py` | screening contract | Additive within a `schema_version`; renaming or removing a field raises `schema_version` |
| `rule_id` values | published record identifiers | `data/rules/*.json` | rules data | Never reused or renamed. A retired rule keeps its ID out of service; a replacement gets a new ID |
| `GET /health`, `POST /intake/extract`, `POST /explain`, `POST /ask`, `POST /staff-questions` | AI service routes | `src/permit_pathways/ai/service.py` | AI service | Additive only. A breaking change ships a new route beside the old one until no published page calls the old one |
| `permit-ai-service` meta tag | page-to-service wiring | `check.html`, read by `assets/ai.js` | web pages | Renamed only in the page and `assets/ai.js` in the same change |
| `day`, `count`, `expires_at` | DynamoDB key and attributes | `src/permit_pathways/ai/budget.py`; `deploy/ai-service/main.tf` (`hash_key`, TTL) | AI service | Never renamed in place: stored items and the TTL setting use these names. A change writes the new name and reads both until the old items expire |
| `PERMIT_AI_PROVIDER`, `PERMIT_AI_MODEL`, `PERMIT_AI_AWS_REGION`, `PERMIT_AI_ROOT`, `PERMIT_AI_ALLOWED_ORIGINS`, `PERMIT_AI_DAILY_CAP`, `PERMIT_AI_PER_CLIENT_PER_MINUTE`, `PERMIT_AI_BUDGET_TABLE` | Lambda environment variables | `deploy/ai-service/main.tf`, `src/permit_pathways/ai/` | AI service | Renamed only in the Terraform and the service in the same deploy; never by find-and-replace in one of them |
| `permit_pathways` | Python import package | `src/permit_pathways/` | package | Kept as the import name after the repository rename; a rename would ship a compatibility shim for one release |
